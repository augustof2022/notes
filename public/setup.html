2. Enable Google sign-in and Drive

Configure this once for the app. Each person then chooses Continue with Google, authorizes app-created files, and saves images in their own private Note images folder. Supabase holds file IDs and searchable text. No public sharing links are created.

  1. Choose a project in Google Cloud Console and enable Google Drive API.
  2. Configure Google Auth Platform branding and audience. Add openid, userinfo.email, userinfo.profile, and https://www.googleapis.com/auth/drive.file. While in Testing, add each allowed Google account as a test user.
  3. Create an OAuth client → Web application. Authorized JavaScript origins: https://augustof2022.github.io and http://127.0.0.1:5173. Origins have no repository path.
  4. Authorized redirect URI: https://wrkoxjlzdeiffdtgbyvq.supabase.co/auth/v1/callback. If using another Supabase project, use that project's Google callback instead.
  5. In Supabase → Authentication → Sign In / Providers → Google, enable Google and enter the OAuth client ID and client secret there. Keep the secret out of Note settings, frontend environment variables, GitHub, and chat.
  6. Allow the Note site in Supabase's redirect URLs, for example https://augustof2022.github.io/notes/ and the local URL above.
  7. In Note choose Continue with Google, then grant the Drive permission. New images automatically use that person's Drive. Use the same Google account on every device.
Google may ask you to reconnect after reloading Note or when Drive access expires. Your local images remain saved while uploads wait. Note's Google tokens stay in memory; its saved Supabase session omits Google access and refresh tokens.

For personal use, you may disable new Supabase signups after creating your account. If other people will use Note, keep signups enabled and configure the Google consent audience accordingly. Each account's database records remain private.

3. Publish on GitHub Pages

  1. Put the app source in your GitHub repository. Keep personal notes, backups, and secret keys out of it.
  2. Open Repository Settings → Pages and choose GitHub Actions. The included workflow tests, builds, and publishes on a push to main.
  3. Optional browser-safe repository variables: VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY. Google credentials stay in Supabase's Google provider settings.
  4. Free GitHub Pages needs a public repository. A private repository needs a supported paid plan or a different static host.

Your device boards and backups

Device boards stay separate when you sign in. Use Settings → Cloud sync → Copy this device's boards into my account to migrate them. Email sign-in and Supabase image storage remain available as alternatives.

Use Settings → Preferences & backup → Export backup before clearing browser data. Backups contain private content. Changing the image provider affects new uploads; existing references keep their original provider. Free OCR reads printed English screenshot text.
