This checklist records the initial setup. It does not inspect your account live. After completing the Google steps, use the test in step 6 to confirm everything works.

1. Finish Google app registration

  1. Open Google Auth Platform. Select the Note Canvas project using the project selector at the top.
  2. If the setup wizard is still open at Finish, review Google's User Data Policy, tick the agreement if you accept it, then click Continue → Create.
  3. If you already see Overview, Branding, Audience and Clients in the sidebar, registration is complete. Skip to step 2. If registration has not started, click Get started. Enter app name Note, choose your Google email as User support email, and click Next.
  4. Choose External for Audience, click Next, enter your email for Contact Information, then Next. Review the agreement yourself and finish with Continue → Create.

The app starts in Testing. That is enough to get your own account working. Google's registration instructions.

2. Add the Google accounts that may test Note

Your current Google account has already been added. Use these steps if you want another Google account to test Note.

  1. In Google Auth Platform, open Audience.
  2. Leave Publishing status as Testing for your first setup.
  3. Under Test users, click Add users.
  4. Enter the Google email you will use in Note, plus any other accounts you want to test. Click Save.

While in Testing, each Google account that uses Note must be on this list. You can use one account on multiple devices. Other people do not each need a Cloud project.

3. Add the four required permissions

The four scopes are already saved in Note Canvas. These instructions let you check them or configure a replacement project.

  1. Open Data Access → Add or remove scopes.
  2. Select the four scopes below. If one is missing, add its exact value under Manually add scopes.
  3. Click Update, then Save if shown. Check all four appear in the saved list.
Required scopesopenid https://www.googleapis.com/auth/userinfo.email https://www.googleapis.com/auth/userinfo.profile https://www.googleapis.com/auth/drive.file

drive.file allows Note to work with files it creates or that you explicitly give it access to. Note creates a private Note images folder automatically; you do not need to create or share it yourself. Google's Drive scope documentation.

  4. Under Authorized redirect URIs, click Add URI and paste the Supabase callback below.

5. Put the credentials into Supabase

The Google provider is now enabled and you have saved its credentials. Continue to step 6 to check the complete sign-in and image upload.

  1. Open your Supabase Google provider.
  2. Switch on Enable Sign in with Google.
  3. Replace the current Client IDs value with the generated OAuth Client ID. It ends in .apps.googleusercontent.com.
  4. Replace Client Secret (for OAuth) with the Client Secret from Google Cloud. Both must belong to the same OAuth client; use the existing Web client 1.
  5. Keep Skip nonce checks and Allow users without an email off. Click Save.
Enter the generated ID and secret directly into Supabase yourself. A Google email address is not a Client ID. Keep the secret out of chat, Note settings, GitHub and frontend environment variables.

Supabase URL Configuration is already set to the value below for both Site URL and Redirect URLs. Leave it in place. Supabase's Google login guide.

6. Sign in and test an image

  1. Open Note, click Sign in to sync → Continue with Google, and choose an account you added under Test users.
  2. Google may first show Google hasn't verified this app because Note Canvas is in Testing. Review this warning yourself and decide whether to continue with the app you configured. Then review the consent screen and approve the requested Google identity and app-created Drive file access if you agree. Finish sign-in yourself.
  3. Create a board named Sync test, add a typed note, and paste a screenshot with Ctrl+V.
  4. Press Ctrl+S and wait until the header says Synced. “Saved locally” means device storage; “Sync pending” means the upload has not finished.
  5. In Google Drive, look for Note images and the uploaded image. In Supabase Authentication → Users, your new Note login should appear. Board and image-reference records will appear in the Note tables.
  6. Open Note on your phone or another browser, sign in with the same Google account, and check that the typed note and screenshot appear.

For boards created before signing in, use Settings & storage → Cloud sync → Copy this device's boards into my account. Device boards and signed-in boards stay separate until you copy them.

Costs, access and reconnecting

Standard Drive API use is currently available at no additional cost within Google's quotas; your Drive storage allowance applies. This setup uses OAuth and Drive API. It does not need Cloud Run, a service account, an API key or a paid OCR service. Current Drive limits and pricing.

Testing gets your own account working. For users outside the test-user list, review Audience → Publish app and any branding or verification requirements Google shows. Public GitHub code does not publish your boards or share Drive files.

Keep Drive connected for uploads and image loading

Note remembers a verified short-lived Drive connection across reloads. For automatic renewal after Google expires that access, the app owner must also deploy the private drive-session Supabase Edge Function. This is separate from the initial Google sign-in setup and GitHub Pages deployment.

  1. Run enable-drive-refresh.sql in your Supabase SQL Editor.
  2. Follow the private Drive renewal deployment guide to set the four server-only secrets and deploy the function. Keep the Google secret and encryption key in Supabase Edge Function Secrets.
  3. In Note, open Settings & storage → Images & search → Enable saved Drive access and complete Google consent once. Reopen a board on another device to test an uncached image.

Uploads and image retrieval then share renewal and retry an expired-token request once. Temporary network errors and request limits retry without asking for a new Google consent. Revoked permissions or Google's Testing-mode grant expiry can still require reconnecting. Without the renewal function, valid cached access works until Google expires it. Local images remain saved while uploads wait; previously downloaded images stay cached for offline viewing.
